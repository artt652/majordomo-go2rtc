# Камеры (go2rtc) для MajorDoMo

Камеры через [go2rtc](https://github.com/AlexxIT/go2rtc): просмотр в панели управления, права, показ на терминалах, временный доступ и гостевые ссылки, WebTorrent. Своих камер у MajorDoMo нет — потоки заводятся в go2rtc, модуль берёт из него только имена; адреса и пароли камер остаются в go2rtc.

## Панель управления → «Камеры (go2rtc)»

- **Камеры** — плитки со снимками (только пока плитка на экране); размер плиток — ползунок «Размер» над сеткой (запоминается в cookie браузера: панель управления очищает localStorage), чёткость снимков подстраивается под размер. Нажатие на плитку — живое видео прямо в ней (ещё раз — снова снимки; играть могут несколько плиток): сначала плеер go2rtc напрямую (`video-rtc.js`: WebRTC, MSE, HLS, MJPEG), не пошло — WebRTC через сервер, иначе снимки. В строке под камерой: 🔇/🔊 — звук (если у камеры он есть; на неиграющей плитке — сразу видео со звуком), ⛶ — на весь экран (поток высокого качества), ⤴ — «Поделиться» (гостевая ссылка на срок или WebTorrent), ⚙ — настройки камеры.
- **Настройки камеры** — превью: нажатие — живое видео, ещё раз — снимки, 🔇/🔊 — звук; название и порядок (хранятся в таблице `go2rtc_cameras`, новые потоки go2rtc добавляются сами, пропавшие помечаются), скрыть, звук (есть — кнопка 🔇/🔊 в просмотре, видео начинается без звука, как требует браузер; нет — звук у go2rtc не запрашивается), поток высокого качества, привязка к объекту, кнопка «Создать устройство «Камера»». «Проба» под превью — go2rtc подключается к источнику (как probe в его веб-интерфейсе) и показывает формат, адрес (пароль — `***`), кодеки видео и звука и принимает ли камера звук (микрофон); для потока высокого качества — тоже, ответ go2rtc целиком — в блоке JSON.
- **Настройки** — адрес API go2rtc (и логин, если go2rtc на другой машине или включён `local_auth`), адрес для устройств, RTSP-сервер go2rtc, ожидание первого кадра, WebTorrent.
- **Права** — через модуль ядра «Контроль доступа» (тип `go2rtc`, объект — камера): пользователи, терминалы, время, условия. Для камер без правила — «только администратору» (по умолчанию) или «всем». Права, заданные раньше отметками, переносятся один раз; правило «пользователи + терминалы» переносится только с пользователями (в журнале — строка об этом). Сценарии не ограничены.
- **Ссылки** — действующий временный доступ, гостевые ссылки и ссылки WebTorrent; «Закрыть» — перестаёт работать сразу.

Прямой просмотр включается сам, если у API go2rtc нет логина и пароля. Браузеру нужно разрешение go2rtc на чужой адрес страницы: в `go2rtc.yaml` — `api: origin: "*"`. По HTTPS к http-адресу go2rtc браузер не пустит — тогда видео через сервер.

## Встроенный go2rtc (ветка alpha)

Настройки → go2rtc: **внешний** (как раньше: свой go2rtc на этой или другой машине, камеры берутся из него) или **встроенный** — модуль сам ставит go2rtc и держит его запущенным, а камеры ведутся в модуле.

- **Установка:** кнопка «Установить go2rtc» скачивает закреплённую версию (сейчас v1.9.15) и сверяет sha256: Linux (amd64, i386, arm64, arm, armv6) и Windows — официальные релизы [AlexxIT/go2rtc](https://github.com/AlexxIT/go2rtc), Android (Termux) — сборка [artt652/go2rtc-android](https://github.com/artt652/go2rtc-android). Файл — `cms/go2rtc/` (доступ по ссылке закрыт `.htaccess`).
- **Запуск:** цикл `scripts/cycle_go2rtc.php` (стандартный цикл MajorDoMo — запускается сам): запускает go2rtc, перезапускает, если тот завершился или изменился конфиг, раз в 30 с заводит камеры модуля. Кнопки «Запустить», «Перезапустить», «Остановить» передают команду циклу.
- **Конфиг — строкой** (`-config '{…}'`): порты API (1984), RTSP (8554), WebRTC (8555), путь к ffmpeg. «API доступен из сети» (по умолчанию включено) — для прямого просмотра в браузере и ссылок HTTP для устройств; выключено — API только на `127.0.0.1`.
- **Файл данных go2rtc** (по желанию, «Хранить данные go2rtc в файле»): для того, что go2rtc сохраняет сам — сопряжения HomeKit, входы Xiaomi и Wyze, потоки и пресеты ffmpeg из его веб-интерфейса, `preload`. Запуск: `go2rtc -config <файл> -config '{строка модуля}'` — go2rtc объединяет конфиги, второй побеждает: порты, API, пароль RTSP и `ffmpeg.bin` задаёт модуль, камера модуля с тем же именем перекрывает поток файла, остальные потоки файла видны как камеры go2rtc. Пишет go2rtc только в первый (файл); камеры модуля в файл не попадают — при включённом файле они передаются строкой, изменение — перезапуском go2rtc. Файл по умолчанию — `cms/go2rtc/go2rtc.yaml.php`: первая строка `# <?php exit; ?>` — для go2rtc комментарий YAML, а по ссылке веб-сервер выполняет её как PHP и отдаёт `# `. Так файл закрыт при любых настройках веб-сервера — `.htaccess` и правила `nginx.conf.sample` действуют не везде (готовый контейнер Docker отдаёт `.ini` и `.log`). Строку модуль возвращает при каждом запуске, если её стёрли в редакторе go2rtc; копии при импорте и журнал go2rtc (`go2rtc.log.php`) — так же. Свой путь — вне сайта (в Docker — на томе, например `/data/go2rtc/go2rtc.yaml`: файл переживёт пересоздание контейнера) или `cms/go2rtc/….php`.
- **Адрес сайта для гостевых ссылок** (поле в настройках, например `https://home.example.com`): гостевые ссылки строятся от него. Не задан — от адреса, по которому открыта страница, а в сценарии без страницы — от адреса сервера для устройств.
- **Видео в браузере через сервер (PHP)** («Видео в браузере через сервер (PHP)»; по умолчанию выключено): страница «Камеры», гостевые ссылки и вставки не подключаются к go2rtc напрямую и не используют WebRTC — PHP читает поток go2rtc и отдаёт по HTTP (`api.php/module/go2rtc/mp4`, в Safari — `hls`). Нужно там, где порт WebRTC недоступен (вне дома, Docker без проброса порта). Цена: процесс PHP на каждого зрителя, задержка несколько секунд, звук только AAC (кодеки H.264/H.265 + AAC). Без настройки порядок прежний: напрямую → WebRTC (согласование через сервер) → если не пошло, то же видео через PHP → снимки.
- **Адрес go2rtc для устройств** (поле в настройках): если задан, по нему строится и ссылка на веб-интерфейс, и ссылки для устройств. Для ссылок через сервер и гостевых ссылок (когда запроса из браузера нет) он же подменяет `127.0.0.1`/`localhost` в BASE_URL (порт сервера остаётся). go2rtc получает этот адрес кандидатом WebRTC (`webrtc.candidates`): в Docker он знает только адрес контейнера, и без этого видео не идёт — остаются снимки.
- **Пароль API из сети** («Пароль для доступа к API из сети» — включается вручную; логин `admin`, пароль создаётся сам): веб-интерфейс go2rtc и API из сети — по логину, модуль с этой машины ходит без пароля (`local_auth: false`). Прямого просмотра в браузере тогда нет (просмотр — через сервер, WebRTC). Ссылки HTTP (MP4, HLS, MJPEG) и снимки устройствам выдаются через сервер: `api.php/module/go2rtc/mp4|hls|mjpeg|frame` по подписи на час, поток читает PHP и отдаёт дальше — каждый зритель занимает процесс PHP, пока смотрит (RTSP — напрямую, без PHP). Пароль API устройствам не отдаётся.
- **API из сети без пароля** разрешён: под настройкой пароля показано предупреждение. Это свойство go2rtc, а не модуля: любой, кто достучался до API, может заводить потоки, а источники `ffmpeg:` и `exec:` запускают программы на машине; с файлом данных ещё и `/api/config` отдаёт пароли камер и токены. Открывайте API только в доверенной сети.
- **Ограничить API списком путей** (`api: allow_paths`, по желанию): остаются просмотр (`/api`, `/api/ws`, `/api/webrtc`, кадр, MP4, MJPEG, HLS), закрыты `/api/config`, `/api/streams` (адреса камер с паролями), журнал, перезапуск, сопряжения и веб-интерфейс go2rtc — и для сети, и для самого модуля. Поэтому камеры модуля при включении задаются только строкой конфига (изменение — перезапуском go2rtc), «Проба», проверка источника и WebTorrent недоступны, список потоков модуль берёт из своих камер и файла данных. Это не замена паролю: просмотровые пути go2rtc принимают адрес источника в запросе и заводят поток на лету.
- **Импорт конфига go2rtc** (панель → «Импорт конфига go2rtc»): загрузка файла, путь на сервере или «Взять из внешнего go2rtc» (`/api/config` по адресу и логину внешнего режима). Конфиг становится файлом данных (прежний — рядом, `go2rtc.yaml.<дата>.bak.php`), файл включается, go2rtc перезапускается.
- **Камеры:** вкладка «Камеры» → «Добавить камеру»: имя потока, адрес, логин и пароль (отдельно от адреса, в списках не показываются), второй адрес высокого качества (поток `имя_hq`). «Проверить» — временный поток и кадр, ошибка go2rtc — прямо в форме. Обычные источники (`rtsp://`, `rtmp://`, `http://`, `onvif://`, `ffmpeg:` без пробелов) заводятся через API на лету — go2rtc 1.9.15 прячет в `/api/streams` логин и пароль. `exec:`, `echo:`, `expr:` и строки с пробелами go2rtc через API не принимает — они идут в конфиг, цикл перезапускает go2rtc (камеры прерываются на 1–2 с).
- **ffmpeg** — свой: Termux — `pkg install ffmpeg`, Linux — `apt install ffmpeg`, Windows — `ffmpeg.exe` (путь в настройках). Без него нет снимков с камер H.264 и перекодирования.

Не проверено: Windows, Android (Termux) с модулем; KSWEB не поддерживается.

## Привязка к объекту

Как в модуле onvif: объект, свойство «в сети», метод при смене состояния; свойство «зрители» (сколько смотрят сейчас); свойство «показать» — записать `Кухня` или `Кухня:30`, и камера появится на терминале (30 с). Проверка раз в минуту (фоновой задачей, только если есть привязанные камеры): кадр из кэша go2rtc за 3 с, зрители — из `/api/streams`.

«Создать устройство «Камера»» создаёт устройство (класс `SCameras`) и записывает в него `streamURL`, `streamURL_HQ` (RTSP go2rtc) и `snapshotURL` (кадр из API go2rtc; если у API есть логин — он попадёт в адрес), а проверка вызывает его `keepAlive`. Можно и привязать камеру к своему объекту вручную.

## Вставка в сцены и страницы

```
[#module name="go2rtc" cam="door" mode="snapshot" width="320" height="180" caption="Дверь"#]
```

Готовый код — на странице камеры (⚙), внизу, блок «Код для сцены». `cam` — имя потока или номер камеры; `mode="snapshot"` — снимки, нажатие — на весь экран, `mode="live"` — сразу видео (если у камеры есть звук — кнопка 🔇/🔊 в углу); `muted="0"` — сразу со звуком (браузер может не дать без нажатия на страницу — тогда без звука; в окне на весь экран, открытом нажатием, звук включится всегда). Права проверяются для того, кто открыл страницу. Подписанные ссылки живут сутки и обновляются страницей раз в 6 часов (`/ajax/go2rtc.html?op=renew`). Для внешних страниц (iframe) — `go2rtcEmbedUrl($name, $exp, $mode)` → `api.php/module/go2rtc/embed?…`.

## Входы `api.php/module/go2rtc/…`

| Адрес | Что |
|---|---|
| `frame?src=…&exp=…&sig=…` (`&w=` — ширина, `&last=1` — последний сохранённый кадр без ожидания камеры) | кадр камеры по подписанной ссылке |
| `whep?src=…&exp=…&sig=…` | согласование WebRTC (POST, SDP) по подписанной ссылке; видео идёт с go2rtc напрямую |
| `embed?src=…&exp=…&mode=…&sig=…` | страница просмотра одной камеры для iframe по подписанной ссылке |
| `guest/<id>` | гостевая страница просмотра одной камеры без входа, до срока ссылки |
| `frame/<id>`, `whep/<id>`, `check/<id>` | кадр, WebRTC и проверка ссылки для гостевой страницы |

`api.php` ядра доступ не проверяет, поэтому модуль пускает только по подписи (секрет модуля) или по действующей гостевой ссылке. Права проверяет тот, кто выдаёт ссылку: панель, вставка, другой модуль. Пароль API go2rtc на устройства и в браузер не уходит.

## Для других модулей и сценариев

```php
include_once(DIR_MODULES . 'go2rtc/go2rtc_lib.inc.php');
if (defined('GO2RTC_API') && go2rtcEnabled()) {
    $file = go2rtcSnapshot('door');                       // снимок в cms/cached/go2rtc (или свой каталог вторым аргументом)
    go2rtcShow(getTerminalsByName('Кухня', 1)[0], 'door', 30);  // показать на терминале 30 с
}
```

| Функция | Что |
|---|---|
| `go2rtcEnabled()`, `go2rtcStreams()`, `go2rtcHas($name)` | настроен ли модуль, имена камер, есть ли камера |
| `go2rtcAllowed($name, $terminal, $user_id, $is_admin)`, `go2rtcAllowedNow($name)`, `go2rtcCamerasFor(...)` | права на камеры (правила «Контроля доступа») |
| `go2rtcCameraList()`, `go2rtcCameraTitle($name)` | камеры из таблицы модуля, название |
| `go2rtcEmbedUrl($name, $exp, $mode, $absolute)` | страница камеры для iframe |
| `go2rtcSignedUrl('frame' / 'whep', $name, $exp, $absolute)` | подписанная ссылка на кадр или WebRTC до `$exp` |
| `go2rtcFrame($name, $width)`, `go2rtcSnapshot($name, $dir)` | кадр (JPEG), снимок файлом |
| `go2rtcUrl($name, $format)` | ссылка для устройства: `rtsp`, `mp4`, `hls`, `mjpeg`, `frame`, `webrtc` |
| `go2rtcShow($terminal_rec, $name, $duration, $title, $level)` | показ на терминале: PiPup — окно (RTSP или WebRTC), плеер с экраном — через очередь «Терминалов» (полоса `camera`) |
| `go2rtcLinkCreate($cam, 'chat' / 'guest', $minutes, $members, $by, $by_title)`, `go2rtcLinkGet()`, `go2rtcLinkClose()`, `go2rtcLinks()`, `go2rtcLinkCameras($keys)`, `go2rtcGuestUrl($id)` | временный доступ участникам чата и гостевые ссылки |
| `go2rtcShare($name)`, `go2rtcUnshare($name)`, `go2rtcShares()` | WebTorrent |

Просмотрщик для страниц — `templates/go2rtc/js/viewer.js` (`go2rtcViewer(элемент, {frame, whep, direct, player, live, …})`, на весь экран — `go2rtcViewer.open({...})`): первым — последний сохранённый кадр (`cms/cached/go2rtc/last_*.jpg`, обновляется не чаще раза в 10 минут), снимки без мигания и только на экране, «нет связи» после 20 с неудач, живое видео — плеер go2rtc напрямую, затем WebRTC через сервер.

## Установка

1. Скачать архив ветки: [`alpha.tar.gz`](https://github.com/artt652/majordomo-go2rtc/archive/refs/heads/alpha.tar.gz) (встроенный go2rtc) или [`main.tar.gz`](https://github.com/artt652/majordomo-go2rtc/archive/refs/heads/main.tar.gz).
2. **Панель управления → Маркет дополнений → «Добавить/обновить вручную»** → выбрать скачанный файл → **«Загрузить и установить»**. Маркет сам снимает верхний каталог архива (`majordomo-go2rtc-alpha/`) и не трогает `README.md` MajorDoMo.

   Без Маркета — распаковать архив и скопировать каталоги `modules`, `templates`, `languages`, `scripts`, `img` в корень MajorDoMo, затем открыть модуль в панели управления.
3. При первом открытии создаются таблицы `go2rtc_links`, `go2rtc_cameras` и подписка на `MINUTELY`; настройки камер из прежней полной версии «Терминалов» переносятся один раз.
4. Режим — на вкладке «Настройки»: **внешний** go2rtc ставится отдельно (свой, на этой или другой машине, в Docker, Termux); **встроенный** (ветка `alpha`) модуль ставит сам кнопкой «Установить go2rtc», а запускает цикл `cycle_go2rtc`. Если цикл не появился в «Циклах» — перезапустить MajorDoMo.

Обновление — так же: новый архив через «Добавить/обновить вручную», поверх. Совместимо с PHP 7 и 8.
